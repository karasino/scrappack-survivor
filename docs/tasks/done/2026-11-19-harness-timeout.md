# Общий таймаут harness и завершение собственных процессов

## Цель и критерии готовности

test:harness ограничен общим временем выполнения, включая зависание worker или дочерней фикстуры. При превышении срока команда сообщает причину, завершает принадлежащие запуску процессы и возвращает exit 124. Обычный успех, ошибки, reporter, дополнительные тестовые файлы и Ctrl+C сохраняют понятный результат; посторонние процессы не затрагиваются.

## Решения и границы

19.11.2026 пользователь поддержал отдельное предложение после приёмки harness-report-guard. Наблюдение: sandbox-запуск потребовал Ctrl+C при --test-timeout=15000; точная причина зависания не установлена. Добавляется внешний Node runner для test:harness: общий лимит 60 секунд, ограниченный cleanup с TERM/KILL, SIGINT → 130, SIGTERM → 143. Первый повод остановки сохраняется. CLI --timeout-ms позволяет проверить короткий лимит; некорректные значения отклоняются до запуска тестов. Список файлов остаётся в package.json, повторного запуска нет.

Некоторые фикстуры создают отдельные process groups через spawnCaptured. Их владение и индивидуальный cleanup сохраняются. Новый runner передаёт детям уникальную метку в окружении, учитывает список владельцев вложенных запусков и на Linux находит свои живые процессы через /proc даже после осиротения. Перед сигналом группе повторно проверяются PID, время старта и PGID; группа supervisor исключена. Переменные окружения не выводятся в диагностику. Сам supervisor свою метку не получает. NODE_TEST_CONTEXT снимается при запуске нового CLI, чтобы Node не пропускал вложенный набор как рекурсивный. Независимый обзор выявил риск объединения групп; этот вариант не применяется.

Обход sandbox, новые зависимости, изменение игровых правил и распространение таймаута на остальные наборы не входят. Поддержан Linux проекта и CI с доступным /proc; другие платформы получают явный отказ до запуска. Намеренное удаление метки/смена окружения потомком не входит в гарантию владения.

## План

1. Добавить внешний runner, общий deadline, сохранение исходных кодов и обработку сигналов. Сохранить command/reporters и передачу дополнительных файлов.
2. Обеспечить cleanup основной и отдельных принадлежащих фикстурам групп без поиска и завершения процессов по порту или имени.
3. Проверить реальные CLI: успех/ошибка, пустой отчёт, зависший тест и потомок, игнорирующий TERM, выход лидера раньше потомка, сигналы, посторонний процесс, вложенный запуск, невалидные аргументы и остановка check с exit 124. Фикстуры и временные профили остаются тестовыми.
4. Запустить целевые проверки и полный check, обновить документы, передать ручной CLI-чек-лист. После подтверждения закрыть задачу и сделать локальный коммит.

## Контрольная точка

Сделано: внешний runner и учёт своих групп через наследуемую метку добавлены без изменения индивидуального cleanup фикстур. Добавлены девять регрессий CLI/таймаута/сигналов/потомков/вложенного запуска/check и намеренно зависающая ручная фикстура. В ходе проверок исправлены наследование NODE_TEST_CONTEXT, допустимый PGID 0 посторонних потоков ядра и гонка создания потомка между снимками /proc. Независимое концептуальное ревью уточнило границы, проверки SIGKILL/поздних групп и защиту от повторного использования PID. Полный check прошёл: 101 core, 49 harness и Canvas/WebGL. В sandbox короткий общий лимит сработал без Ctrl+C; точные команды фикстуры и Ctrl+C в PTY проверены автоматически. После завершения запусков живых процессов с меткой harness не осталось. 19.11.2026 пользователь подтвердил все четыре ручные CLI-проверки без замечаний. Задача закрыта, документация обновлена; реализация и документы подготовлены к закрывающему локальному коммиту. Оставшейся реализации и блокировок нет.

Оставшиеся после неуспешного cleanup группы удалены отдельно по точной метке владельца с перепроверкой PID/starttime; итоговый поиск не нашёл оставшихся принадлежащих групп. Сырые данные окружения не выводились.
- Последний npm run test:harness в разрешённой среде — exit 0, 49 именованных сценариев, [core-report] Verified 49 executed scenarios across 4 files. Проверены сохранение обычных diagnostics, границы аргументов, TERM/KILL/INT, отдельные группы и их позднее создание, потомки после выхода лидера, вложенный запуск, сохранение постороннего процесса и реальная остановка агрегатора с 124.

- npm run check — полный последовательный прогон прошёл с exit 0: doctor → docs → 101 core с Verified → 49 harness с Verified → build → сценарии → бой → исследование → сборка. Все браузерные наборы прошли в Canvas/WebGL; прежнее предупреждение о крупном JS-чанке сохраняется. Негативные проверки launcher отработали как ожидалось.

- npm run test:harness -- --timeout-ms 0 — ожидаемый exit 2 до запуска тестов.
- npm run test:harness -- tests/fixtures/core-empty.mjs — все 49 обычных сценариев прошли, Node показал pass 50, но общий reporter сохранил ожидаемый exit 1 и имя пустой фикстуры.

- После подтверждения ручной приёмки повторены npm run check:docs и git diff --check — успешно. Код не менялся; полный прогон повторно не запускался.

## Ручная приёмка

19.11.2026 пользователь подтвердил успешное прохождение всех четырёх ручных CLI-проверок; принято без замечаний. Ниже сохранён принятый чек-лист из корня проекта в обычном Linux-терминале с Node 24 и установленными зависимостями. Перепрохождение игры не требовалось.

1. Запустить намеренно зависающую тестовую фикстуру:

   ```bash
   node scripts/run-harness.mjs --timeout-ms 2000 tests/fixtures/harness-hang.mjs
   ```

   Ожидаются HANG READY, Timed out after 2000 ms, Cleanup complete и exit 124 без Ctrl+C. После короткого cleanup возвращается приглашение терминала; отсутствие Verified для прерванного набора ожидаемо.
2. Повторить эту команду с --timeout-ms 30000. После HANG READY нажать Ctrl+C. Ожидаются Interrupted, Cleanup complete и exit 130; ждать 30 секунд не нужно.
3. Запустить npm run test:harness -- --timeout-ms 0. Ожидаются сообщение о допустимом целом диапазоне, exit 2 и отсутствие выполнения сценариев. Затем npm run test:harness — exit 0 и [core-report] Verified 49 executed scenarios across 4 files. Настройка предыдущего запуска не сохраняется.
4. Запустить npm run test:harness -- tests/fixtures/core-empty.mjs. Ожидаются успешные обычные сценарии, [core-report] FAIL tests/fixtures/core-empty.mjs: no internal node:test summary и exit 1. Штатный pass 50 ожидаем, но не отменяет отказ. Повторный обычный npm run test:harness снова проходит с 49 сценариями и exit 0.

## Известные проблемы

Общий deadline ограничивает ожидание, но не устраняет ограничения sandbox. Cleanup поддержан на Linux с доступным /proc и наследуемой меткой; намеренное изменение/скрытие окружения потомком не входит в гарантию. Подтверждённых незакрытых дефектов после последнего полного прогона нет.
