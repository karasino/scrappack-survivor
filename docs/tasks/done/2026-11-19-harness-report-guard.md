# Проверка выполнения внутренних harness-сценариев

## Цель и критерии готовности

test:harness подтверждает выполнение внутренних node:test-сценариев каждого выбранного файла и отклоняет отчёт только с файловыми pass. Обычный вывод и исходные ошибки сохраняются; число сценариев не фиксируется. Полный check останавливается при отказе test:harness.

## Решения и границы

19.11.2026 пользователь согласовал предложенное после приёмки core-report-guard отдельное улучшение: распространить тот же контроль на test:harness, проверить успешный прогон и отказ неполного отчёта. Подключается существующий scripts/core-report.mjs; имя файла, экспорт и префикс [core-report] сохраняются для совместимости. Формулировки ошибок обобщаются для обоих наборов. Игровой код, зависимости и остальные направления roadmap не меняются.

## План

1. Подключить дополнительный reporter к test:harness вместе со spec без повторного запуска тестов.
2. Проверить точную npm-команду в изолированном временном проекте: реальные сценарии во всех выбранных файлах проходят, пустой файл рядом с ними вызывает отказ. Расширить регрессию остановки check на test:harness с настоящим reporter.
3. Проверить реальный test:harness в ограниченной и разрешённой средах, выполнить полный check, обновить документы и передать CLI-чек-лист.
4. После ручного подтверждения пользователя закрыть задачу и сделать локальный коммит.

## Ручная приёмка

19.11.2026 пользователь подтвердил успешное прохождение всех трёх ручных CLI-проверок; принято без замечаний. Ниже сохранён принятый чек-лист из корня проекта в обычном терминале с Node 24 и установленными зависимостями; перепрохождение игры не требовалось.

1. Запустить npm run test:harness. Ожидаются имена 40 сценариев, exit 0 и [core-report] Verified 40 executed scenarios across 3 files. Число 40 относится к текущему набору и не зафиксировано в guard; префикс общего reporter сохранён намеренно.
2. Запустить npm run test:harness -- tests/fixtures/core-empty.mjs. Ожидаются успешные обычные сценарии, exit 1 и [core-report] FAIL tests/fixtures/core-empty.mjs: no internal node:test summary. Файловый pass пустой фикстуры и итог pass 41 в штатном выводе Node ожидаемы: guard отклоняет неполный отчёт. Рабочие файлы менять не нужно.
3. Снова запустить npm run test:harness, затем npm run test:core. Обе команды должны завершиться с exit 0 и Verified: 40 сценариев в 3 файлах и 101 в 7 соответственно. Добавленная аргументом фикстура не сохраняется в обычной команде.
