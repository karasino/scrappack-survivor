# Независимые core-тесты

## Цель и критерии готовности

Быстро проверять правила инвентаря, энергии, боя, исследования и сборки без Chrome, Vite, Phaser, CDP и локального сервера. Сейчас чистые проверки запускаются внутри браузерных evaluate и повторяются для Canvas/WebGL. Отделить их от проверок интерфейса, сохранив проверяемое поведение и обычный процесс ручной приёмки.

- `npm run test:core` запускает настоящий код src/game/core напрямую в Node 24. Команда работает без установленного Chrome, при неверном CHROME_BIN и занятом порте 4175, не вызывает общий browser doctor и не открывает сетевые порты.
- Перенесены прежние чистые сценарии; для каждого записано, где он проверяется после переноса. Равенство количества assertions не заменяет сохранение покрытия.
- Полный забег seed 123 выполняется в Node один раз; Canvas/WebGL сохраняют проверки реального ввода, отображения и связи UI с core.
- Полный check включает новый набор один раз; существующие игровые команды проходят, их оставшееся browser-покрытие не урезано.
- Измерены время test:core и полного check на той же машине до/после; опубликованы фактические результаты, без произвольного порога производительности для CI.

## Решения и границы

17.11.2026 пользователь поддержал выделение core-тестов и попросил описать задачу, следующие улучшения и сделать коммит для продолжения в новой сессии. Этот коммит сохраняет план; реализация ещё не начиналась, статус approved не означает принятую реализацию.

### Среда запуска

- Использовать стандартные `node:test` и `node:assert/strict`. Новые тесты и helpers — обычные ESM `.mjs`, как существующие тесты проекта; проверяемые модели остаются TypeScript.
- Добавить только devDependency `tsx` и обновить lockfile. Он загружает TypeScript с нынешними относительными импортами без расширений. Встроенное удаление типов Node само эти импорты не разрешает; не менять ради тестов исходники игры и не строить отдельную CommonJS-копию core.
- Команда Node: `node --import=tsx --test --test-timeout=15000` с явно перечисленными файлами `tests/core/inventory.test.mjs`, `energy-combat.test.mjs`, `exploration.test.mjs`, `crafting.test.mjs`, `run.test.mjs` (все внутри tests/core). Явные пути исключают случайный запуск helpers или старых browser-файлов.
- Тесты напрямую импортируют реальные `.ts`-модули из src/game/core. Не использовать browser `/src/...` URLs, строковый evaluate, сериализацию функции через toString или копии игровых расчётов. Допустимы обычные фикстуры и явные ожидаемые результаты.
- tsx не проверяет типы: текущий `npm run build` продолжает проверять TypeScript исходников. Тесты остаются JavaScript, отдельная TS-конфигурация тестов и @types/node для этого этапа не нужны.
- При реализации подобрать совместимую с Node 24 версию tsx и зафиксировать её lockfile; остальные зависимости не обновлять попутно. Не использовать npx с возможной загрузкой пакета во время проверки.

Матрица выше — исходная карта. При реализации дополнить её конкретными именами новых тестов в [verification.md](../../verification.md). Подготовку фикстур не удалять, пока она нужна оставшимся UI-проверкам; убрать ненужные глобальные связи только после проверки потребителей. Pure UI-helpers вроде подготовки tooltip не считать core и не втягивать представление в Node-набор этой задачи.

Полный маршрут перенести в `tests/core/scenarios/full-run.mjs`, общие Node-фикстуры — в `tests/core/fixtures.mjs` при реальном повторном использовании. Отдельные тесты не зависят от порядка или состояния соседних тестов. Browser-фикстуры могут отличаться по назначению; не создавать общий адаптер evaluate для сохранения старых строковых тестов.

### Ограничения

Не менять игровые API, баланс, действия, производственные импорты, UI, сцены и TypeScript strict. Не вводить production test hooks, новый тестовый framework, покрытие ради процента, watch-службу, CI или новые игровые сценарии вместо переноса имеющихся. Если обнаружится независимый баг игры, описать его отдельно, не подгонять ожидания ради зелёного прогона.

Обоснование выбора: [Node 24 о TypeScript и расширениях импортов](https://nodejs.org/docs/latest-v24.x/api/typescript.html), [tsx и Node test runner](https://tsx.hirok.io/testing), [tsx не выполняет type checking](https://tsx.hirok.io/typescript).

## Автоматические проверки

17.11.2026 при подготовке плана проверены текущие файлы и существующие импорты. Успешно выполнены `npm run check:docs` и `git diff --check`; игровые исходники, тесты, scripts и зависимости не изменены. Работоспособность нового подхода в проекте пока не проверялась; игровые наборы ради одного плана повторно не запускались.

После реализации обязательны:

- `npm run test:core`: весь Node-набор, повторный прогон с тем же seed и понятные имена сценариев.
- Тот же набор при несуществующем CHROME_BIN и занятом 4175; чужой процесс остаётся нетронутым. Проверки не создают сервер и не требуют разрешения на сетевой listen; ограничения sandbox на дочерние процессы учитывать отдельно.
- Намеренно неверное ожидание во временной копии: ненулевой exit code, имя проваленного сценария, ограниченное завершение без оставшихся процессов. Ошибочную фикстуру не коммитить.
- Полный seed 123: 7 боёв, 52 перемещения, 2 боевые аптечки, 76 HP, 5 × 4, Heavy Battery из заработанных компонентов и завершение демо. Не телепортировать героя и не подменять ресурсы в этом маршруте; отдельные unit-фикстуры допустимы для краёв.
- `npm run check`: новый набор ровно один раз, прежний test:harness и все оставшиеся browser-наборы в Canvas/WebGL. Отдельно убедиться, что game build проверяет типы, а не полагается на tsx.
- `npm ci` в чистой временной копии, документация/ссылки, отсутствие изменений src и проверенные времена до/после. Не объявлять экономию времени до измерения.

## Известные проблемы

Текущие core-импорты не содержат расширений; прямой native Node import без загрузчика не является готовым решением. Существующие browser-файлы смешивают чистые проверки и UI, а некоторые используют globalThis, поэтому перенос нельзя выполнять удалением целых файлов без инвентаризации.

tsx ещё не установлен и реальная совместимость выбранной версии будет проверена при реализации. tsx не проверяет типы. Текущий полный check требует Chrome/порта; автономность гарантируется именно новой командой test:core. Ускорение пока не измерено. Strict TypeScript, права на графику и отзыв прежнего GitHub-токена остаются отдельными вопросами.
