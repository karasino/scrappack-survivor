# Ситуационный Scrap Brute, BRACE и безоружная атака

## Цель и критерии готовности

Игрок видит фиксированное намерение врага и выбирает атаку, лечение или защиту с учётом энергии. Scrap Brute реагирует на своё здоровье и сильное попадание; обычные враги сохраняют постоянный ответ. Отсутствие выбранного оружия не блокирует ход. Preview совпадает с выполнением, обе раскладки работают в Canvas/WebGL, оба полных маршрута seed 123 проходимы с заработанными ресурсами.

## Решения и границы

План согласован в чате и передан пользователем на реализацию 19.11.2026. Босс: 66 HP, STRIKE 14; при HP ≤ 40% REPAIR +12 вместо удара, два применения и cooldown четыре последующих хода. Попадание ≥ 12 запускает WIND-UP без урона, затем SLAM 22 с cooldown четыре последующих хода. Приоритет: подготовленный SLAM → REPAIR → WIND-UP → STRIKE. Первое намерение STRIKE; триггеры не накапливаются. Смертельный удар сохраняет атакующий ответ, погибший босс не лечится.

BRACE доступен во всех боях: floor(итоговый щит выбранной брони × 2), план питания только брони; при нулевом щите отказ без хода. Оружейные свойства и наступательные свойства брони не действуют. Без выбранного оружия END TURN выполняет UNARMED с базовым уроном 2; свойства брони действуют как при атаке, минимум урона 1. Ошибочный/множественный выбор не превращается в кулаки. Drag снимает выбор, preview показывает UNARMED.

Горение, новые сектора и общий пересмотр баланса не входят. Используем нынешний harness; JSON-диагностика отложена. Подготовленный scrap-brute добавляется в текущий launcher, отдельный runner не создаётся.

Ниже сохранён чек-лист приёмки. Основные пункты используют штатный launcher и обычное управление, без консоли и изменения ресурсов. Для восстановления начала: Enter в терминале и повторить команду.

1. Запустить `npm run scenario -- scrap-brute`. Ожидаются Scrap Brute 66/66, герой 70/100, выбранные Arc Baton и Makeshift Vest, NEXT ACTION / STRIKE · 14 damage. Дважды нажать END TURN: герой 64/100, босс 42/66, SLAM · 22 damage. Нажать BRACE: SHIELD LAST 16, HIT LAST 6, герой 58/100, босс 42/66, SLAM cooldown 4. Быстрый двойной клик не добавляет второй ход.
2. Снять выбор Makeshift Vest: BRACE недоступна с причиной Select armor with a positive shield.; клик ничего не меняет. Выбрать её снова. Ещё два END TURN: босс 18/66, герой 46/100, NEXT ACTION / REPAIR · Heal up to 12 HP; батарея под бронёй удалена, BRACE preview SHIELD 4. Снять выбор Arc Baton и нажать END TURN: UNARMED 2, босс после лечения 28/66, герой остаётся 46/100, REPAIR uses left 1, REPAIR cooldown 4. Кулаки не расходуют заряд оружейных батарей.
3. Восстановить сценарий. Переставить батарею под Makeshift Vest из (2,2) в (3,3): после завершения drag усиление брони исчезает, BRACE показывает SHIELD 4. Вернуть батарею в (2,2): SHIELD 16. Во время переноса боевые действия заблокированы, HP и намерение не двигаются. Координаты считаются с нуля.
4. Выбранный Arc Baton начать переносить, нажать R и отпустить над краем правой панели вне рюкзака. Положение и ориентация восстанавливаются, выбор остаётся снятым, preview явно UNARMED. END TURN выполняет удар кулаками; повторный короткий клик по Arc Baton возвращает обычную атаку. Повторить отмену переноса через resize и уход фокуса: HP, заряд и намерение сохраняются.
5. Сузить окно до 800 × 600 и вернуть широкий вид: NEXT ACTION, BRACE и оба preview читаются и принимают по одному действию. Восстановить сценарий с `npm run scenario -- scrap-brute --renderer canvas` и повторить первый пункт.
6. Лечение: в восстановленном сценарии нажать HEAL +25 (2) на первом STRIKE. Герой 89/100, босс 66/66, один Medkit потрачен; это боевой ход с ответом врага, без атаки и расхода оружия. После завершения забега NEW RUN очищает намерение/кулдауны и возвращает стандартный стартовый набор.

## Известные проблемы

Общий баланс ранее не принят и не принимается автоматически этой задачей. Наблюдения о harness: раньше launcher не имел отдельной ситуации босса; scrap-brute добавлен в существующую подготовку. Диагностика сохранила причину перезагрузки Vite, но короткий вывод сначала показывал ReferenceError и предыдущее название проверки: для разбора понадобился failure.json/server stdout. Пока собираем наблюдения без новой инфраструктуры.

Кандидат на улучшение после наблюдений на 2–3 игровых задачах: явный отказ Page reloaded during check с текущей группой при неожиданной перезагрузке страницы. Польза — сразу отличать потерю тестового контекста от ошибки игры. Проверка — контролируемая правка исходника во временном checkout во время UI-прогона, ожидаемый отказ с причиной и группой, затем успешный контроль без правки. Штатную загрузку и предусмотренные переходы исключить. Предложение не согласовано как новая задача; JSON-диагностика остаётся отложенной.
