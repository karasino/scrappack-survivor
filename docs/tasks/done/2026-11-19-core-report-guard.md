# Проверка выполнения внутренних core-сценариев

## Цель и критерии готовности

npm run test:core не должен считаться успешным при отсутствии подтверждённых внутренних node:test-сценариев хотя бы в одном выбранном файле. Читаемый штатный вывод и диагностика ошибок сохраняются; число сценариев не фиксируется. Команда остаётся независимой от Chrome, порта и doctor.

## Решения и границы

19.11.2026 пользователь поддержал предложенное после приёмки процедурных секторов отдельное улучшение harness: контроль внутренних сценариев в структурированном отчёте и отрицательная фикстура отчёта без сценариев. Это согласование новой реализации; игровые правила, UI, версии зависимостей и остальные этапы roadmap не меняются.

В установленном Node 24.15.0 проверены события test:summary: полный поток содержит отдельный итог каждого файла, ограниченная среда — только общий итог успешных файлов. Дополнительный reporter проверяет внутренние итоги всех явно выбранных файлов и окончательный итог запуска. Suites, skip, TODO и отменённые тесты не считаются выполненными сценариями. Reporter spec продолжает показывать имена, исходные ошибки и итог. При отсутствии доказательства — ненулевой exit code с именем файла; автоматического ослабления проверки или запуска вне sandbox нет.

## План

1. Добавить небольшой проверяющий reporter и чистый валидатор структурированных итогов Node. Подключить его к существующей команде test:core вместе со spec, сохранив один запуск набора и явный перечень файлов.
2. Проверить полные/неполные отчёты по файлам, suites, skip/TODO, обычный отказ и ошибки загрузки/timeout; добавить реальные CLI-фикстуры, включая пустой файл с успешным штатным файловым результатом.
3. Проверить настоящий test:core в ограниченной и разрешённой средах, отрицательную фикстуру и полный check. Обновить README/verification/roadmap, передать короткий ручной список CLI-команд.
4. После подтверждения пользователя закрыть задачу и сделать локальный коммит.

## Контрольная точка

Сделано: reporter и чистый валидатор добавлены к test:core без повторного запуска набора и изменения списка файлов; README/verification/roadmap обновлены. Реальный ограниченный запуск отклонён с exit 1 и диагностикой всех семи файлов; разрешённый подтвердил 101 сценарий в 7 файлах с exit 0. Прошли 38 harness-регрессий, включая настоящие CLI и остановку агрегатора на отказе reporter. Первая TypeScript-фикстура вне проекта потребовала собственного type:module; исправлено, повтор успешен. Полный check прошёл, независимое концептуальное ревью существенных рисков не выявило. 19.11.2026 пользователь подтвердил все три ручные CLI-проверки без замечаний. Задача закрыта, документация обновлена; код и документы входят в закрывающий локальный коммит. Оставшейся реализации и блокировок нет.

## Автоматические проверки

19.11.2026:

- npm run test:core в sandbox — ожидаемый exit 1: штатный итог 7 успешных файлов, reporter указал отсутствие внутренних итогов каждого. Это подтверждённый отказ недостаточного отчёта, не провал игровых правил.
- npm run test:core в разрешённой среде — exit 0, 101 именованный сценарий, строка Verified 101 executed scenarios across 7 files.
- npm run test:harness — 38 тестов прошли после исправления ESM-окружения временной TypeScript-фикстуры. Пустая CLI-фикстура даёт native exit 0 без guard и exit 1 с ним; исходные diagnostics assertion/import/timeout сохранены.
- npm run check — полный последовательный прогон прошёл: doctor → docs → 101 core с Verified → 38 harness → build → сценарии → бой → исследование → сборка. Все браузерные наборы прошли в Canvas/WebGL; прежнее предупреждение о крупном JS-чанке сохраняется. Ожидаемые негативные проверки launcher не являются отказом полного check.
- Точная ручная команда node --test --test-reporter=./scripts/core-report.mjs tests/fixtures/core-empty.mjs проверена агентом: ожидаемый exit 1, сообщение FAIL с точным именем фикстуры. Это автоматическая проверка команды, не ручная приёмка пользователя.
- npm run check:docs и git diff --check — прошли.
- После подтверждения ручной приёмки повторены только npm run check:docs и git diff --check — успешно. Игровой код не менялся; полный прогон повторно не запускался.

## Ручная приёмка

19.11.2026 пользователь подтвердил успешное прохождение всех трёх ручных CLI-проверок; принято без замечаний. Ниже сохранён принятый чек-лист из корня проекта в обычном терминале с Node 24 и установленными зависимостями. Перепрохождение игры не требовалось.

1. Запустить npm run test:core. Ожидаются имена реальных сценариев, exit 0 и строка [core-report] Verified 101 executed scenarios across 7 files. Число 101 относится к текущему набору и не зафиксировано в валидаторе.
2. Запустить отрицательную фикстуру:

   ```bash
   node --test --test-reporter=./scripts/core-report.mjs tests/fixtures/core-empty.mjs
   ```

   Ожидаются exit 1 и [core-report] FAIL tests/fixtures/core-empty.mjs: no internal node:test summary. Это намеренно пустой тестовый файл; отказ подтверждает работу защиты. Рабочие core-тесты менять не нужно.
3. Запустить npm run test:harness. Ожидаются 38 именованных тестов, включая core report и aggregate check stops at test:core, exit 0. Ожидаемые отказы CLI-фикстур обрабатываются тестами и не делают harness красным.

## Известные проблемы

Зелёный итог семи файлов в ограниченной среде не доказывает выполнения внутренних сценариев; новый reporter автоматически отклоняет такой результат. Сам reporter не снимает ограничения среды. Прочих подтверждённых проблем нет.
