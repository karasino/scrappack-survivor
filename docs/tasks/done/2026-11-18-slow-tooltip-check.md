# Проверка tooltip при замедлении браузера

## Цель и критерии готовности

Добавить автоматическую проверку обновления уже открытого tooltip при замедлении CPU через Chrome DevTools Protocol в Canvas и WebGL. Питание и заряд должны обновляться без движения курсора. Отключение обновления должно приводить к ограниченному timeout с последним видимым текстом и обычными артефактами отказа.

## Решения и границы

18.11.2026 пользователь согласовал предложенное улучшение harness и поручил добавить проверку перед переходом в новую сессию. Использовать существующие Chrome/CDP runner и фикстуры, замедление CPU в 6 раз только внутри нового сценария, сброс rate:1 через finally. Ожидать конкретное состояние, без фиксированной задержки как критерия успеха. CPU throttling не гарантирует заданную частоту кадров. Игровой код и production API не менять; новые зависимости не нужны.

## План

1. Добавить изолированный smoke-сценарий: питание Laser Pistol, нехватка/возврат заряда и текст/процент заряда батареи при неподвижном курсоре.
2. Включить его в test:combat-ui (значит также check и CI) и дать отдельную короткую команду test:slow-ui для воспроизведения.
3. Во временной версии теста отключить refresh после открытия tooltip: подтвердить exit 1, осмысленный timeout и JSON/PNG; восстановить тест и подтвердить успех.
4. Выполнить полный npm run check, обновить verification и контрольную точку для новой сессии.

## Известные проблемы

Новых дефектов игры или проверки не выявлено. При первом полном запуске наблюдался нативный сбой Chrome; отдельный exploration и повторный полный check прошли без изменения кода. Причина нативного сбоя не установлена, диагностические артефакты сохранены. GPU/Chrome стабильность не объявляется исправленной этой задачей. Исходная зависимость старого теста от паузы 50 мс исправлена в принятой задаче чертежей; новая проверка расширяет защиту от подобных ошибок.

Предложение для будущего улучшения harness: сохранять CDP-события падения renderer в failure.json и сообщать о них сразу, даже когда основной процесс Chrome жив. Это поможет отличать нативный сбой от ошибки импорта или timeout. Проверка пользы: искусственное crash-событие в тесте runner даёт ограниченный отказ с правильной причиной и диагностикой. В эту задачу реализация не входит.
