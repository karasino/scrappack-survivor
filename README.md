# Scrappack Survivor

Roguelike с электрическими цепями предметов в рюкзаке. Phaser рисует игру внутри Canvas/WebGL; TypeScript собирается через Vite. Язык игрового интерфейса — английский.

## Локальное окружение

- Node.js **24.x**, npm из этого окружения. Версия указана в [.nvmrc](.nvmrc); с установленным nvm достаточно `nvm use`.
- Для браузерных проверок и полного check: Google Chrome с поддержкой headless и Canvas/WebGL. По умолчанию `google-chrome`; для другого расположения передать `CHROME_BIN=/absolute/path/to/chrome`.
- Зависимости берутся из [package-lock.json](package-lock.json), обновление зависимостей не является частью обычного запуска.

```bash
npm ci
npm run doctor
npm run check
```

`doctor` проверяет среду и локальный порт **4175**, но ничего не устанавливает и не останавливает чужие процессы. Для Chrome используются временный профиль и программный WebGL (SwiftShader). Проверки требуют разрешения на запуск браузера и прослушивание `127.0.0.1`; `EPERM` означает ограничение среды, а не провал игровой механики.

После `npm ci` правила можно проверять отдельно: `npm run test:core`. Команда не требует Chrome, Vite или свободного порта, не вызывает doctor и напрямую импортирует TypeScript core в Node через tsx. Проверка типов остаётся в `npm run build`.

## Запуск игры

```bash
npm run dev
```

Открыть адрес из вывода Vite. WASD/стрелки или клик по соседней клетке — шаг, Space — ожидание, E — контекстное действие, B — переключение компактного вида, R — поворот переносимого предмета. Рюкзак управляется мышью. `NEW RUN` начинает новый забег после завершения.

## Проверки

| Команда | Результат |
| --- | --- |
| `npm run doctor` | Диагностика Node, зависимостей, Chrome и порта |
| `npm run check:docs` | Ссылки, бюджеты кратких документов, структура задач |
| `npm run test:core` | Правила инвентаря, энергии, боя, исследования, сборки и полный seed 123 без браузера |
| `npm run build` | TypeScript и production-сборка |
| `npm run test:combat-ui` | Ввод в бою, связь UI с энергопланом, тултипы и визуальные состояния |
| `npm run test:visual` | Только визуальная часть боевого набора |
| `npm run test:exploration` | Ввод исследования, связь UI с RunState, переходы и раскладки |
| `npm run test:crafting` | UI материалов, сборки, лечения, наград и модалок |
| `npm run test:harness` | Регрессии диагностики и проверки документов |
| `npm run check` | Doctor → документы → core → harness → build → бой → исследование → сборка |

Браузерные наборы проверяют Canvas и WebGL. Запускать их последовательно: они используют общий порт 4175. Core-набор запускается в полном check один раз. При изменении правил начинать с test:core, затем выбирать UI-наборы по [матрице](docs/verification.md). Снимки и диагностика — в игнорируемом Git каталоге `artifacts/`. Подробности — [в правилах проверки](docs/verification.md).

## CI

[Workflow](.github/workflows/ci.yml) запускается для pull request, push в `main` и вручную через Actions. На отдельных Ubuntu 24.04 runners выполняются `Core, harness and build` и `Browser UI (WebGL and Canvas)`: собственные `npm ci`, Node 24, закреплённый Chrome for Testing в браузерном задании. Полный `check` внутри CI дополнительно не вызывается.

Логи установки и `Doctor` доступны в шагах; браузерные JSON/PNG загружаются в `diagnostics-browser-<run_id>-<attempt>` на семь дней. При раннем сбое PNG может отсутствовать; первичная ошибка остаётся в логе. Обновление Chrome и проверки отказа описаны [в verification](docs/verification.md). Workflow подготовлен локально; прогоны GitHub ещё ожидаются.
