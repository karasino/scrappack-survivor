# Задача Scrappack Survivor

Применять для изменения игры или её harness, продолжения незавершённой реализации и обработки результатов ручной проверки. Обычный вопрос об игре сам по себе не требует создания задачи.

Пути ниже отсчитываются от корня репозитория. Сначала прочитать [AGENTS.md](../../../AGENTS.md), если его инструкции ещё не доступны, и [docs/status.md](../../../docs/status.md). Открыть только активную задачу и документы по теме из маршрутов AGENTS; архив — только по историческому вопросу.

## Начало или продолжение

Сверить git status/diff с активной задачей. Для новой задачи использовать [шаблон](../../../docs/tasks/_template.md) и [формат](../../../docs/tasks/README.md). Не заменять незавершённую задачу молча. Внести цель, выбранные решения и согласование из чата; неизвестные предпочтения уточнить, обнаружимые факты проверить по коду.

После согласования работать по плану. После содержательного этапа и перед передачей записать сделанное, оставшееся и следующий шаг в том же файле. Не копировать сырые логи и переписку. Расхождение контрольной точки с кодом исправлять по фактам, сохраняя согласованное намерение.

## Проверка и завершение

Выбрать проверки из [матрицы](../../../docs/verification.md). Записать реально выполненные команды и ограничения отдельно от ручной приёмки. Обновить затронутые документы поведения и выдать русский чек-лист обычным управлением; перевести задачу в awaiting-manual.

Замечания пользователя возвращают задачу в implementing. Только подтверждённые пункты считать принятыми. После необходимого подтверждения выполнить закрытие из формата задач: accepted, перенос в done, указатель status, локальный коммит. Уже выданное согласование не запрашивать повторно.

В конце принятой задачи предложить одно обоснованное улучшение harness, если есть наблюдаемая польза. Новую реализацию начинать в рамках отдельного согласованного запроса.
