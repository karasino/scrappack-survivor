# Архитектура и источники состояния

Читать при изменении границ подсистем. Механики описаны по маршрутам [AGENTS.md](../AGENTS.md).

## Границы

- [main.ts](../src/game/main.ts) создаёт Phaser с AUTO renderer и FIT. Версии читать из package/lock; `strict` сейчас не включён в [tsconfig.json](../tsconfig.json).
- [core](../src/game/core/) — TypeScript без Phaser: модели, команды, чистые расчёты и данные секторов/предметов.
- [GameScene](../src/game/scenes/GameScene.ts) связывает ввод, команды core и представления. Обычная встреча, переход сектора и переключение раскладки не перезапускают сцену.
- [ui](../src/game/ui/) рисует предметы, карту, мастерскую, модалки, тултипы. Геометрия/цвета принадлежат UITheme, текстуры — ItemPresentation. DOM не используется для игрового интерфейса.

## Владение данными

`RunState` владеет забегом: HP, inventory, миром, RNG, активной встречей, материалами, столом, переносимым предметом, известными рецептами, тайниками/отложенным выбором и наградами. BlueprintGenerator создаёт согласованные предложения отдельным RNG; ItemVariants содержит совместимость и описания свойств. `ExplorationEngine` разрешает мировой ход; `CombatEngine` — боевое действие. Чистый SectorGenerator создаёт карту и размещение всех объектов по seed/sector отдельным RNG из профилей SectorDefinitions. RunState загружает результат; BlueprintGenerator получает позиции тайников из этого результата, сохраняя собственный поток предложений. Представление использует результаты команд.

`Item` хранит уникальный ID, стабильный definitionId, ориентацию, неизменяемый вариант, собственные характеристики, связи питания и выбор. Экземпляр имеет ровно одного владельца: рюкзак, клетка, стол или перенос. Координаты и связи нельзя независимо копировать в UI как второй источник истины.

`Inventory.updatePowerGrid()` определяет физические соединения; `EnergyPlan` чисто определяет доступность усиления и оплату. previewCombatAction чисто рассчитывает действие со свойствами выбранной сборки; preview и выполнение используют одну функцию. Tooltip получает собственные итоговые характеристики из core. Числа каталога и секторов не дублировать как вторую таблицу баланса.

## Режимы и жизненный цикл

Режимы RunState: `exploration`, `combat`, `workshop`, `boss-reward`, `defeat`, `complete`. Команды проверяют режим и владение. Предметы/заряд/HP сохраняются между встречами и секторами; завершение и новый забег — отдельные действия.

Модальное окно блокирует игровой ввод. Shutdown удаляет собственные обработчики, визуалы и таймеры; повторный старт не удваивает их. Resize/blur отменяют перенос с восстановлением владельца и ориентации.

При изменении этих связей читать [бой](mechanics/combat.md), [владение и сборку](mechanics/crafting-progression.md), [UI](ui.md) только в затронутых частях.
